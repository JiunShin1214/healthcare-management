# Roadmap

이 문서는 Health Navigator-Management 백엔드의 구현 예정 및 확장 계획을 정리합니다.

## OCR 결과 DB 저장

현재 OCR 결과는 API 응답으로 JSON 형태로 반환됩니다. 향후 OCR로 추출한 건강검진 수치, 판정 결과, 누락 필드, 원본 OCR 텍스트를 DB에 저장할 수 있는 테이블을 추가할 예정입니다.

저장 대상은 현재 `health-navigator-backend/app/schemas/health_check.py`의 `HealthCheckResponse`와 `health-navigator-backend/app/services/parser_service.py`의 결과 구조를 기준으로 설계할 예정입니다.

- 원본 OCR 텍스트
- 파싱 상태
- 누락 필드 목록
- 이름, 주민등록번호 일부, 생년월일, 나이, 성별
- 건강검진 수치
- rule-based 판정 결과

## 로그인 사용자 기준 건강검진 결과 저장

로그인한 사용자만 OCR 결과를 저장할 수 있도록 인증 기반 저장 API를 추가할 예정입니다.

프론트엔드에서는 로그인 상태에 따라 저장 버튼을 활성화하거나 비활성화하고, 백엔드에서는 JWT 인증을 통해 실제 저장 가능 여부를 최종 검증하는 구조를 고려하고 있습니다.

화면 제어는 Flutter에서 처리하더라도, 최종 저장 권한은 백엔드에서 `get_current_user` 기반으로 확인하는 방식이 필요합니다.

## OCR 결과 수정 및 재판정

OCR 결과가 잘못 인식되거나 누락된 경우 사용자가 수치를 직접 수정할 수 있도록 수정 API를 추가할 예정입니다.

수정된 값은 기존 rule-based 판정 로직을 다시 적용하여 건강 상태 결과도 함께 갱신하는 방향으로 확장할 수 있습니다.

## 의약품 검색 자동완성

현재 의약품 검색은 검색어 기반 조회 방식입니다. 향후 사용자가 한 글자 이상 입력하면 후보 의약품 목록을 반환하고, 사용자가 목록에서 선택할 수 있도록 자동완성 API를 개선할 예정입니다.

기존 `drug_items.item_name`과 `drug_items.item_seq` 기반 검색 로직을 확장하여 구현할 수 있습니다.

## 인체 UI 기반 증상/질병 확인

Flutter 화면에서 인체 UI의 특정 부위를 선택하면, 해당 부위와 관련된 증상, 통증 강도, 추가 정보를 입력하거나 선택할 수 있도록 확장할 예정입니다.

입력 방식은 두 가지 방향을 검토 중입니다.

- 객관식 선택 기반: 신체 부위, 증상, 통증 강도 등을 정해진 선택지로 입력
- 자연어 입력 기반: 사용자가 증상을 문장으로 입력하고, AI 또는 LLM을 활용해 구조화

현재는 신체 부위와 질병을 안정적으로 매핑할 수 있는 한국어 데이터셋을 조사 중입니다. 영어 기반 데이터는 존재하지만, 한국어 서비스에 적용하기 위해서는 번역, 용어 표준화, 질병명 매핑 과정이 필요합니다.

1차 백엔드 방향은 `가능성 있는 질환 후보`와 `참고 정보`를 반환하는 API입니다. 확정 진단이나 처방은 제공하지 않으며, 위험 신호가 감지되면 후보 목록보다 의료기관 방문 안내를 우선합니다.

인체 UI의 1차 큰 부위 범주는 `head_face`, `eye`, `ear_nose_throat`, `neck_shoulder`, `chest`, `abdomen`, `pelvis_urinary`, `back_waist`, `arm_hand`, `leg_foot`, `skin`, `general`의 12개로 고정합니다.

초기 API 후보는 다음과 같습니다.

- `GET /symptom-checker/body-regions`
- `GET /symptom-checker/contexts`
- `GET /symptom-checker/body-regions/{region_id}/symptoms`
- `POST /symptom-checker/assess`

자세한 설계 초안은 `docs/SYMPTOM_CHECKER.md`에 정리합니다. 데이터셋 후보와 라이선스 검토는 `docs/SYMPTOM_CHECKER_DATASETS.md`에 분리합니다.

## ML/XAI 기반 건강 분석 확장

현재 건강 상태 판정은 rule-based 방식으로 구현되어 있습니다. 향후 사용자의 생활 컨텍스트, 예를 들어 전날 과식, 운동량, 수면 부족, 음주 여부 등을 함께 반영하여 머신러닝 기반 분석으로 확장할 예정입니다.

또한 SHAP 기반 XAI를 적용하여 어떤 건강검진 수치나 생활 정보가 결과에 영향을 주었는지 설명 가능한 형태로 제공하고, 이를 시각화하는 방향을 고려하고 있습니다.

## LLM 기반 자연어 증상 입력 보조

증상 입력을 자연어로 받을 경우, LLM을 활용해 사용자의 문장을 구조화된 증상 정보로 변환하는 방식을 검토할 수 있습니다.

예를 들어 사용자가 증상을 문장으로 입력하면, 이를 신체 부위, 통증 양상, 지속 시간, 강도 등의 필드로 정리하는 방식입니다.

다만 의료적 판단을 LLM이 직접 수행하는 방식은 위험할 수 있으므로, LLM은 진단을 내리는 역할이 아니라 사용자 입력을 정리하거나 검색 후보를 좁히는 보조 역할로 제한하는 방향이 적절합니다.
